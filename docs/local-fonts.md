# Local Fonts and Privacy-First Delivery

Owners and administrators can open **Site structure > Local fonts** to host
licensed web fonts below `public_html/assets/fonts` and control external font
requests in generated public CSS.

## Delivery modes

- **Remote and local** preserves existing Google Fonts imports and also emits
  registered local `@font-face` rules. This is the backward-compatible default.
- **Local only** emits registered local faces but no Google Fonts imports.
- **System only** emits neither remote imports nor local font-face rules. Theme
  family names then fall back to the visitor's available system fonts.

The mode affects `/cms/theme.css`. It does not rewrite hand-authored HTML or
custom CSS under `public_html`; audit those files separately when external
requests must be eliminated completely.

## Upload and registration

1. Upload a WOFF2, WOFF, TTF, or OTF file, up to 10 MB.
2. Enable **Register font face** beside the stored file.
3. Enter its CSS family name, weight or variable range, and style.
4. Save font settings and regenerate public pages.
5. Open Theme settings and use exactly the same family name for body, heading,
   or monospace typography.

Use a numeric weight from `100` through `900`. Variable fonts can use an
ascending range such as `100 900`. A file can be deleted only after its face is
unregistered. Up to 32 files and 16 registered faces are supported.

Uploads are verified from their binary signature rather than trusting the file
extension. Stored names are generated by the CMS, symbolic links and path
traversal are rejected, and font-setting changes use regeneration rollback.

## Licensing and source control

Local hosting does not grant redistribution rights. Confirm that each license
permits web embedding and self-hosting. `public_html/assets/fonts/*` is ignored
by Git by default to reduce accidental publication in an open-source repository.
Use protected deployment storage or explicitly force-add only fonts whose
licenses permit repository redistribution.

PostgreSQL backups preserve registrations and the delivery mode, but not font
files. Back up `public_html/assets/fonts` separately. A restore is complete only
when both the database setting and matching files are present.

## Existing installations

No migration is required. Older `public_theme_v1` values normalize to **Remote
and local** with no registered local faces, preserving existing Google Fonts
behavior. Theme reset and starter-kit application preserve the selected font
delivery mode and local registrations.
